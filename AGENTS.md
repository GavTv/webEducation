# Инструкции для AI-агентов

## О проекте

My Work Chat — приложение для учебных групп и общения. Клиент — Next.js, React и TypeScript; API — Express и Sequelize; данные хранятся в PostgreSQL. Production-клиент работает на `https://my-workchat.ru`, API развёрнут на Render.

## Архитектура

- В клиенте соблюдай Feature-Sliced Design: `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
- UI и маршруты страницы оставляй в `client/src/app`; переиспользуемый UI выноси в подходящий FSD-слой.
- Общение с API и WebSocket держи в `client/src/shared/lib` либо в API-модулях соответствующей сущности или фичи.
- В сервере маршруты, контроллеры, сервисы, модели и middleware остаются в своих существующих каталогах `server/src`.
- Клиент не обращается к PostgreSQL напрямую. Доступ к данным реализуется на сервере и защищается JWT и проверкой членства в группе.
- Интерфейс приложения — на русском языке. Стили страницы держи рядом с ней; не переноси оформление в один глобальный файл.

## Рабочие правила

- Перед изменением проследи путь данных целиком: компонент → API-клиент → маршрут → контроллер → сервис → модель.
- Сохраняй существующий контракт API, если задача не требует его изменить. При изменении обновляй клиент и сервер вместе.
- Не обходи проверки доступа ради отображения данных. Не возвращай парольные хеши, токены или секреты в ответах API.
- Секреты и пользовательские данные не добавляй в Git. Используй `.env.example` для имён переменных без реальных значений.
- Для интерфейсных изменений проверь мобильную и широкую раскладки, состояния загрузки, ошибки и пустые данные.
- Не добавляй тестовые учётные записи и данные в production.

## Роли помощников

| Роль | Фокус |
|---|---|
| Frontend | React, TypeScript, FSD, доступность и адаптивная раскладка |
| Backend | Express, проверка запросов, JWT, Sequelize и PostgreSQL |
| Security reviewer | Авторизация, права доступа, валидация, секреты и персональные данные |
| Integration reviewer | Соответствие API-контрактов клиенту, конфигурация Vercel/Render и запуск проекта |

Назначай роли только если доступны отдельные агенты и работа действительно делится на независимые части. Иначе выполни проверки последовательно и сверь интеграцию сам.

## Локальный запуск

- Клиент: `cd client && npm install && npm run dev`.
- Сервер: `cd server && npm install`, скопируй `server/.env.example` в `server/.env`, настрой PostgreSQL и секреты, затем `npm run migrate` и `npm run dev`.
- Клиент по умолчанию подключается к API через `NEXT_PUBLIC_API_URL`; production использует API на Render.
